### 任务 2.3：结果合理性检查

**做什么**：检查生物学结果是否"看起来对"

**通俗解释**：  
就像体检报告出来后，医生要看指标是否在正常范围。计算机说"运行成功"不代表结果正确，需要人工判断结果是否符合生物学常识。

**检查要点**：

**LEfSe检查**：
- 生物标志物数量：10-500个（太少=无差异，太多=过拟合）
- LDA分数：顶部>3.0，最小≈2.0
- 富集方向：case和control数量不应相差>10倍

**Core Microbiome检查**：
- 核心菌丰度占比：>70%（健康），40-70%（疾病），<40%（高异质性）
- 核心菌数量：细菌100-500，真菌10-50，病毒5-20
- 分组特异性：Case-specific和Control-specific数量相近

**Functional Redundancy检查**：
- FDI值：细菌5-15，真菌3-8，病毒1-5（维度递减）
- 无NaN或Inf值
- 病毒FDI不应大于细菌FDI

**Pathway Activity检查**：
- Pathway数量：50-300条
- 贡献度分散性：每条pathway贡献度>1%的物种≤10个

**为什么重要**：  
生物信息分析最怕"garbage in, garbage out"。通过检查能及早发现数据问题或分析错误。

**验收标准**：  
- [ ] 所有指标在合理范围内
- [ ] 无明显异常信号（如全0、全NA）
- [ ] 结果可解释（符合该队列的生物学背景）

### 任务 2.4：与已知文献对比

**做什么**：将结果与该队列的已发表研究或生物学预期对比

**通俗解释**：  
就像考试答案对标准答案。如果是CRC队列，核心菌中应该能看到已知的CRC相关菌。如果LEfSe发现的biomarker和文献报道完全相反，需要排查问题。

**常见队列的预期**：
- CRC队列: Fusobacterium↑case, Roseburia↓case
- T2D队列: Lactobacillus↓case, Prevotella copri↑case
- IBD队列: 核心菌<50%（高异质性）

**为什么重要**：  
通过与已知知识对比，能及早发现数据问题或分析错误。

**验收标准**：  
- [ ] LEfSe结果中≥50% top biomarker符合文献预期
- [ ] Core microbiome的丰度占比在该疾病的合理范围
- [ ] FDI的维度大小关系符合理论

## 🔧 阶段4：系统集成与自动化（优先级：🟡 重要）

### 任务 4.1：真菌维度完善

**做什么**：创建真菌MetaPhlAn4合并规则

**通俗解释**：  
目前真菌数据是"半成品"（有每个样本的profile，但没有合并表）。就像买菜买了食材，但还没洗切配好。现在要补全这个步骤。

**具体操作**：
在 pipeline/rules/mycobiome.smk 添加：
```python
rule fun_metaphlan4_merge:
    input:
        expand(WORKDIR + "/result/fungi/metaphlan4/{sample}/{sample}_profile.txt", sample=SAMPLES)
    output:
        WORKDIR + "/result/fungi/metaphlan4/merged/taxonomy.tsv"
    shell:
        "merge_metaphlan_tables.py {input} > {output}"
```

**为什么重要**：  
补全后，Core Microbiome和Functional Redundancy的真菌分析就不再需要条件跳过，能得到完整的三维度结果。

**验收标准**：  
- [ ] rule fun_metaphlan4_merge 创建完成
- [ ] 测试运行成功生成 fungi/metaphlan4/merged/taxonomy.tsv
- [ ] 修改 statistics.smk 中真菌输入为显式文件（去除条件判断）
